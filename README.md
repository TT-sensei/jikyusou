# 持久走チャレンジ

タブレットで使える、学校・学級向けの持久走記録サイトです。

個人で自分の記録を積み上げる「個人モード」と、教師が出席番号を選びながらクラス全員の記録を登録する「クラスモード」の2つを用意しています。

公開サイト: https://tt-sensei.github.io/jikyusou/
リポジトリ: https://github.com/TT-sensei/jikyusou

## 1. 主な機能

- 個人モードで周回を記録
- クラスモードで出席番号ごとに記録
- 1周・半周の入力
- 1周あたりの距離を設定
- 周回数から走行距離を自動計算
- 今日の記録と累計を表示
- 個人の目標を設定
- 目標をmまたは周で設定
- 100段階の達成メダル
- メダル基準をmまたは周から選択
- バッジコレクションを選択
- 達成時に5枚ずつバッジを表示
- 達成証をCanvasで生成
- 達成証をPNG保存・印刷
- 学校・学年・組・コース距離などを設定
- 設定済みURLを配布
- 共有URLでは先生向け設定をロック
- localStorageによる端末内保存

## 2. 入口

通常のURLを開くと入口画面が表示されます。

「個人で記録する」と「クラスで記録する」から選択します。

通常URL:
 /jikyusou/

個人モード:
 /jikyusou/#personal

クラスモード:
 /jikyusou/#class

設定パラメータを含む共有URLは、入口を経由せず個人モードを直接開きます。

## 3. 個人モード

1人分の記録を管理します。

表示・保存する主な情報:

- 名前
- 学校・学年・組
- 1周の距離
- 自分の目標
- 目標のひとこと
- 今日の周回
- 累計周回
- 累計距離
- 目標までの残り
- 達成メダル
- 記録履歴

周回は1周単位だけでなく半周単位でも入力できます。

内部では半周を0.5として計算します。

例:
1周 → 200m
2周 → 400m
2周＋半周 → 500m

## 4. クラスモード

クラスモードは、教師が児童の記録を順番に入力するためのモードです。

基本操作:

1. 出席番号を選択
2. 周回数を入力
3. 「この記録を登録」を押す

名前の登録は必須ではありません。

名簿が未登録でも、出席番号だけで記録できます。

クラス画面の最上部にはクラス累計を表示します。

- クラス累計距離
- クラス累計周回数

を確認できます。

同じ児童を何度登録しても、その都度加算されます。

## 5. 出席番号と名前

クラスモードでは、出席番号を記録の基本キーとして扱います。

名前は補助情報です。

例えば12番の児童に名前を登録すると、

12番　山田

のように表示されます。

名前を登録しなくても、

12番

として利用できます。

名前を後から変更しても、12番を基準に過去の記録との対応が保たれます。

このため、名前入力を最初から必須にする必要がありません。

## 6. 名簿

「名簿を登録」から1〜40番の名前を登録できます。

40人すべてを入力する必要はありません。

例:

1番　田中
2番
3番　佐藤
4番
5番　鈴木

のような部分登録も可能です。

名前を空欄にすると、その番号は名前なしで扱います。

名簿はクラスモード専用のlocalStorageに保存します。

## 7. クラス記録

クラスモードでは記録を履歴として追加します。

例えば、

12番　2周
12番　3周
12番　1周＋半周

と登録すると、12番の累計は6周＋半周になります。

現在のクラスモードは、同じ端末で教師が記録を蓄積する利用を基本としています。

複数端末間でリアルタイム同期する機能はありません。

## 8. 周回と距離

「1周の距離」を設定し、その値から距離を計算します。

例えば1周=200mなら、

1周 = 200m
2周 = 400m
2周＋半周 = 500m
5周 = 1000m

となります。

画面には「1周＝○m」が分かるようにコース情報を表示します。

## 9. 個人目標

個人モードの目標はmまたは周で設定できます。

例:

5000mを目指す
20周を目指す

目標には短い「ひとこと」も設定できます。

目標とメッセージは別々に保存します。

## 10. 100段階メダル

メダルは全部で100段階です。

現在の基準:

- 1〜50段階: 100mごと
- 51〜100段階: 200mごと

代表的な段階:

- 1段階 = 100m
- 10段階 = 1000m
- 50段階 = 5000m
- 75段階 = 10000m
- 100段階 = 15000m

メダル定義は data/medals.js に分離しています。

## 11. メダルの単位

メダルの達成基準は「m」と「周」から選べます。

mの場合は累計距離で判定します。

周の場合は累計周回数で判定します。

個人目標の単位とメダルの単位は別設定です。

## 12. バッジコレクション

選択できるコレクションは2種類です。

### いろいろなバッジ

edu-assetsの既存バッジ素材を使用します。

持久走と直接関係する科目別コレクションではなく、さまざまな種類のバッジを組み合わせています。

### シンプルな印

サイト内のシンプルな達成マークを使用します。

コレクション定義は data/medal-collections.js に分離しています。

## 13. バッジ獲得演出

複数のメダルを同時に達成した場合は5枚ずつ表示します。

10枚なら、

1回目: 5枚
2回目: 5枚

という表示になります。

## 14. 達成証

達成したメダルをタップすると達成証を作成できます。

達成証には、達成した距離または周回数、名前、累計記録、学校・学年・組、達成日、ナビキャラクターなどを表示します。

背景にはリポジトリ内の syoujyo .svg を使用しています。

ファイル名に空白があるため、JavaScriptでは ./syoujyo%20.svg として参照しています。

Canvasで画像を生成し、PNG保存または印刷できます。

## 15. 共有URL

教師が設定した内容をURLに含めて配布できます。

例:

?school=○○小学校&grade=6年&class=1組&lap=200&goal=10000

主なパラメータ:

- school
- grade
- class
- lap
- goal
- goalUnit
- medalUnit
- collection

共有URLを開いた場合は個人モードを直接表示します。

## 16. 共有URLのロック

共有URLから開いた場合、先生向け設定は変更できません。

共有される設定には、学校、学年、組、1周の距離、目標、メダル単位、バッジコレクションなどが含まれます。

## 17. 保存

バックエンドやデータベースは使用していません。

基本的にlocalStorageへ保存します。

個人モードとクラスモードは保存領域を分けています。

個人モードは js/storage.js が中心です。

クラスモードは jikyusou-class-v1 という別の保存領域を使用します。

端末やブラウザをまたいだ自動同期はありません。

ブラウザの保存データを消去すると記録も失われる可能性があります。

通常設定、共有URL、共有モード判定を担当します。

js/storage.js

個人モードの周回記録・累計計算を担当します。

js/medals.js
メダル達成判定を担当します。

js/certificate.js
Canvasによる達成証生成を担当します。

js/award.js
メダル獲得時の5枚表示演出を担当します。

js/ui.js
個人モードの画面表示を担当します。

js/app.js
入口、個人モード、クラスモードの起動とイベント処理を担当します。

css/base.css
色、背景、基本タイポグラフィなどを定義します。

css/layout.css
画面全体のレイアウトを定義します。

ボタン、カード、メダル、クラスモードなどの部品を定義します。

css/responsive.css
画面幅に応じた調整を担当します。

## 19. クラスモードの設計方針

クラスモードは「名前を入力しないと使えない」設計にしません。

最小操作は、

出席番号を選ぶ
→ 周回を選ぶ
→ 記録する

です。

名簿を登録している場合だけ名前を表示します。

これにより、名簿準備が終わっていなくてもすぐ使い始められます。

また、教師が同じ児童を何回も記録する場面を想定し、検索や長い入力をできるだけ減らしています。

## 20. UI方針

タブレットでの利用を優先します。

重視していること:

- 大きなタップ領域
- 数字を見つけやすい配置
- 周回入力を大きく表示
- 重要な操作を画面中央に配置
- ドラッグ操作を使わない
- 不要な装飾を増やさない
- できるだけ一画面で主要操作を完結する

クラスモードでは出席番号をボタンとして並べ、タップだけで児童を切り替えます。

狭い画面では番号ボタンの列数を減らします。

## 21. 学校名

特定の学校名はコードに固定しません。

先生が設定画面から入力できます。

同じサイトを別の学校・学年・学級でも利用できるようにしています。

## 22. 技術方針

静的サイトとして動作します。

使用しないもの:

- バックエンド
- データベース
- APIキー
- 有料API
- ビルド環境
- 外部APIへの記録送信

GitHub Pagesへそのまま公開できる構成を基本とします。

## 23. 外部素材

背景やバッジなど、一部の素材は既存のTT-sensei系アセットをURLで参照しています。

特にバッジはedu-assetsの素材を利用しています。

サイトのコードと教育素材は分けて管理し、既存素材を必要以上に複製しない構成を基本とします。

## 24. 今後の拡張候補

クラスモードを中心に、今後次の機能を追加できます。

- 児童ごとの累計一覧
- 日付ごとの記録確認
- 記録の編集・削除
- 名簿の一括登録
- 記録のバックアップ
- 記録の復元
- CSV出力
- 先生用集計画面
- クラス内の記録を見やすくする一覧画面

特にクラスモードは今後大きくなる可能性があるため、必要に応じて記録処理を js/class-records.js などへ分離します。

## 25. 開発方針

機能を1つの巨大なファイルへ詰め込まず、役割ごとに分離します。

データ定義、記録処理、保存、メダル判定、画面表示、達成証、演出を可能な範囲で分けます。

優先するのは機能の多さではなく、

「先生が迷わず設定できる」
「子どもが迷わず記録できる」
「タブレットで押しやすい」

ことです。

## 26. ライセンス・素材

このリポジトリにはコードだけでなく、教育用途のオリジナル素材や既存のTT-sensei系アセットを参照する部分があります。

コード、教材、画像、キャラクター、バッジなどをすべて同一条件で自由に再配布できるという意味ではありません。

学校・家庭などの非営利的な教育利用を想定しています。

コードや素材をまとめて販売したり、オリジナル素材をそのまま再配布したりする用途は想定していません。

素材を利用する場合は、それぞれの素材の利用条件を確認してください。

## 27. 現在の中心的な考え方

このサイトの中心は、持久走そのものをゲーム化することではなく、「走った記録を簡単に残す」ことです。

個人モードでは、自分の記録と目標を確認できます。

クラスモードでは、教師が出席番号を選び、短い操作で記録できます。

名前を必須にしないことで、名簿が準備されていなくても利用できます。

出席番号と名前を分けることで、後から名簿を整えても記録を壊しにくい構成にしています。
